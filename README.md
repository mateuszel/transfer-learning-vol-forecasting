# Forecasting Volatility for New Issues

This project studies whether historical volatility information from mature assets can improve forecasting for newly listed stocks. The main focus is on the trade-off between using more source data and avoiding negative transfer when source and target assets behave differently.

The project compares standard transfer strategies with a similarity-based approach using Dynamic Time Warping (DTW). In addition to forecasting performance, it examines how source selection changes marginal covariate distributions, marginal label distributions, and conditional relationships between covariates and future volatility.

## Main experiments

The main results are presented in `experiment.py`. The notebook evaluates:

- standard HAR and extended HAR models;
- Target Only, Source Only, and Naive Pooling benchmarks;
- DTW-based source selection;
- a distance-weighted extension of DTW-HAR;
- rolling out-of-sample forecasts evaluated with MSE and QLIKE;
- marginal and conditional distribution-shift diagnostics.

The data preparation process is documented in `data_preprocessing.py`. This notebook is the recommended starting point for inspecting the raw data, missing observations, session alignment, gap filling, and construction of the final modelling dataset.

## Data and experimental setting

The experiment uses twelve mature stocks as source assets and two newly listed stocks, CHWY and CRWD, as target assets. The main data period runs from January 2016 to February 2020. The period after February 21, 2020 is excluded to avoid the major market disruption associated with the COVID-19 period.

The processed dataset used by the forecasting notebook is stored at:

```text
data/processed/har_extended_dataset.parquet
```

The raw and processed datasets are included in the repository so that the notebooks can be inspected and run locally without downloading the data again. The scripts in `data/` are provided for rebuilding the raw inputs and require locally configured market-data credentials. Do not commit API keys or other credentials.

## Local installation

Create a virtual environment from the repository root:

```bash
python -m venv .venv
```

Activate it using the command for your operating system:

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

```bash
# macOS / Linux
source .venv/bin/activate
```

Install the dependencies:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Running the notebooks locally

Run the commands below from the repository root so that the relative data paths resolve correctly.

To view the notebooks and their results as read-only applications, use:

```bash
marimo run experiment.py
marimo run data_preprocessing.py
```

The main results are presented in `experiment.py`. The data-preprocessing notebook is useful for inspecting how the dataset was constructed.

If you want to inspect or edit the source code, use the marimo editor:

```bash
marimo edit experiment.py
marimo edit data_preprocessing.py
```

The experiment reads the processed dataset and runs the forecasting and distribution-shift analyses. On a typical local machine, preprocessing takes approximately 2 minutes, while the full experiment takes just under 10 minutes. Some rolling-forecast and Monte Carlo cells account for most of this runtime.

The preprocessing notebook can be used to rebuild the processed dataset. Its final cell writes to `data/processed/har_extended_dataset.parquet`, so it only needs to be rerun when the dataset is being rebuilt.
